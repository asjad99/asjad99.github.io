<p><em>“A computer program is said to learn from experience E with respect to some class of tasks T and performance measureP, if its performance at tasks in T, as measured by P, improves with experience E.”</em></p><hr><p>In Supervised machine learning  we  solve problems like image classification where we learn a concept by showing our learning algorithms a set examples with the hope that it will able to classify them correctly on the future unseen examples.  </p><p>How do we build a such a classifier? well the general recipe is as follows: </p><h3 id="learning-representation-evaluation-optimisation">Learning = Representation + Evaluation + Optimisation</h3><p>We start by choosing a formal language representation which represents the hypothesis space of the learner. This decides what the set of classifiers that it can learn. Then we pick an objective function to evaluate the performance of our classifier. Finally we need a search method for finding the optimal performing classifier.  Overall efficiency of our learner depends on the choice of optimzation method. </p><p>During training we try to evaluate the performance by plotting its “learning curve” which shows the error rate(measured on test set) as a function of training examples. A good learning algorithm achieves an error rate of (almost) zero as you show it more and more examples. The rate at which the curve approaches zeros depends on how difficult the learning task is. </p><h3 id="training-error-and-generalisation">Training error and Generalisation:  </h3><p>The problem with the canonical machine learning problem is that we don't really care about minimizing this objective on the given data set</p><p><br>$$<br>\underset{\theta}{\operatorname{minimize}} \sum_{i=1}^m \ell\left(h_\theta\left(x^{(i)}\right), y^{(i)}\right)<br>$$</p><p>What we really care about is how well our function will generalize to new examples that we didn't use to train the system (but which are drawn from the "same distribution" as the examples we used for training)</p><p>During training, if we pick really flexible models with higher degree polynomials then chances are they would exhibit overfitting. In practice this means, they actually have very low loss on the training data, but create functions we don't expect to generalize well.</p><p>Our Major goal of machine learning is to generalize beyond the examples seen during training. Memorisation is not a good strategy for learners because we often see only a fraction of examples we can will encounter in real world settings. Luckily induction works pretty well, which means by taking certain assumptions ML algorithms are able to figure out knowledge from a small number of examples.  </p><p><em>According to “no free lunch” theorem, no learner can beat random guessing over all possible functions to be learned. </em></p><p>In the classification problem there exists a “ground truth” function <em>'f'</em> specifying the correct classification of every possible data point. <em>'f' </em>is initially unknown and our learners job is to figure out this function. We assume we are given<em> 'n' </em>data points drawn independently and identically<em> (“i.i.d.”)</em> from the distribution <em>'D'</em> along with corresponding labels that represent ground truth. We need to come up with a learning algorithm that uses these data points as clues and outputs prediction function<em> g</em>, which is our best guess as to what actual <em>'f' </em>might be.  </p><p>But the challenging bit is that we want to generalize beyond the training examples so that our learned function can perform well on future unseen examples as well. So what “Learning” really means is that we take the given examples and extrapolating so that <em>g</em> coincides with <em>'f'</em>.  </p><p><em>"The ability to perform well on previously unobserved inputs is called generalization". </em></p><p>How hard is this objective? well generally speaking the more data we have, the more better chance we have of figuring out the ground truth function <em>'f'.</em>  Our success also depends on no. of functions that could be ground truth (fewer the better). But again, Machine learning is not just about optimization where we reduce the training error. what we really care about is the generalization error (or test error), defined as <em>"the expected value of the error on a new input. i.e probability that g disagrees with the ground truth f on the label of a random sample" </em>[2][3].</p><figure class="kg-card kg-image-card"><img src="https://asjadkhan.ghost.io/content/images/2024/07/image-1.png" class="kg-image" alt="" loading="lazy" width="772" height="514" srcset="https://asjadkhan.ghost.io/content/images/size/w600/2024/07/image-1.png 600w, https://asjadkhan.ghost.io/content/images/2024/07/image-1.png 772w" sizes="(min-width: 720px) 720px"></figure><p>As model becomes more complex, training loss always decreases; generalization loss decreases to a point, then starts to increase. </p><p>Although it is difficult to quantify the true generalization error (i.e., the error of these algorithms over the complete distribution of possible examples), we can approximate it by holdout cross-validation. Here the Basic idea is to split the data set into a training set and a holdout set Train the algorithm on the training set and evaluate on the holdout set</p><h3 id="%10computational-learning-theory">Computational Learning Theory: </h3><h3 id=""></h3><p>Folks who are deep into ML theory try to answer some of the big philosophical questions. e.g</p><blockquote> “What does it mean to learn?” , “Can a computer learn?”, "Are there algorithms that can solve certain learning problems in polynomial time?" . </blockquote><p>While its hard to answer them completely, its interesting to ask if we can use some theory to determine the  <strong>efficiency and power of machine learning models? </strong></p><p><strong>PAC-learnability:</strong> </p><p>PAC Learning can be seen as the computational theory equivalent for machine learning and  goes to back to 1984 when <a href="http://en.wikipedia.org/wiki/Leslie_Valiant">Leslie Valiant</a> figured out the idea of learning problems that are feasible (solvable in polynomial time).  </p><p>One of the aims of learning theory is to predict what learning rates are achievable in a given learning task. The PAC model was one attempt (Probably Approximately Correct) to come with such a theory, which  aims to explain the best worst-case learning rate. Though it has been criticised as not capturing the actual behavior of many learning algorithms in practical settings[1]. Still just like <a href="https://en.wikipedia.org/wiki/Computational_complexity_theory">computational complexity theory</a> is useful, PAC and its various subsequent variations try to do the same for machine learning.</p><blockquote>A problem is PAC-learnable if there is an algorithm A which for any distribution D and any concept c will, when given some independently drawn samples and with high probability, produce a hypothesis whose error is small.</blockquote><p>For deep learning models the capacity depends on the optimization algorithm we use and  theoretical understanding of nonconvex optimization is still in its early stages making it hard to determine the capacity of deep learning models. </p><p>We have the option to alter the hypothesis space (i.e the set of functions that the learning algorithm is allowed to select as being the solution). Our challenge here is to choose a model with the right '<em>capacity</em>'. This means we pick Machine Learning models  that match the complexity of task to be solved and the training data available. e.g quadratic model will generalize well if the underlying function is quadratic. </p><p>To better understand  generalization, we can decompose the generalization error into bias and variance. Discussed in the previous post</p><p>Overall, we have to draw a balance between low training error while at the same time try to achieve a small gap between training and test error(generalization). We keep in mind that measuring generalization error this way is proxy method as we don't know the ground truth <em>'f' </em>nor the distribution <em>'D</em>'(that we talked about earlier). </p><hr><p>REFERENCES: </p><p>[1] <a href="https://web.math.princeton.edu/~rvan/tri201106.pdf">https://web.math.princeton.edu/~rvan/tri201106.pdf</a></p><p>[2] <a href="https://www.deeplearningbook.org/contents/ml.html">https://www.deeplearningbook.org/contents/ml.html</a></p><p>[3] <a href="https://web.stanford.edu/class/cs168/l/l5.pdf">https://web.stanford.edu/class/cs168/l/l5.pdf</a></p><p>[4] <a href="https://homes.cs.washington.edu/~pedrod/papers/cacm12.pdf">https://homes.cs.washington.edu/~pedrod/papers/cacm12.pdf</a></p><p>[5] <a href="https://jeremykun.com/2014/01/02/probably-approximately-correct-a-formal-theory-of-learning/">https://jeremykun.com/2014/01/02/probably-approximately-correct-a-formal-theory-of-learning/</a></p>
